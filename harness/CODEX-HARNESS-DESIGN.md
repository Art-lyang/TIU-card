# Codex 하네스 설계안

## 1. 프로젝트 목적 추정

TIU-CARD는 후기 베타/릴리즈 후보 단계의 정적 브라우저 게임입니다. 카드 스와이프 지휘 선택, 분기형 텍스트 어드벤처, 조사테이블/아카이브 시스템, 이브닝 캐릭터 대화, 시설, 로컬 세이브 슬롯, 현장임무 미니게임을 한국 SF 감시 디스토피아 세계관 안에서 결합합니다.

이 프로젝트는 코드 빌드 복잡도보다 콘텐츠와 데이터 연결이 핵심입니다. 주요 위험은 깨진 참조, 스크립트 로드 순서 회귀, i18n 누락, 밸런스/엔딩 도달성 변화, 톤/캐논 불일치입니다.

## 2. 필요한 Codex 에이전트

- `implementation-lead`: 범위가 정해진 구현과 통합.
- `data-integrity-auditor`: ID, LOG, 미션, 아카이브, 증거, i18n, validator 점검.
- `narrative-lore-editor`: 톤, 캐논, 스포일러 경계, 한국어/영어 문구.
- `ui-runtime-debugger`: 브라우저 런타임, 콘솔 에러, 모바일 레이아웃, 정적 React CDN 제약.
- `balance-simulation-analyst`: 시뮬레이터, 엔딩 분포, 루트 도달성, 스탯 압박.
- `release-qa-coordinator`: 최종 QA와 릴리즈 체크리스트.

## 3. 필요한 Codex 스킬

- `data-change-validation`: `data-*.js`와 연결 참조 검증.
- `browser-smoke-qa`: 로컬 정적 서버와 브라우저 스모크 경로.
- `simulation-balance-pass`: 프로필 기반 몬테카를로 점검.
- `i18n-content-pass`: 한국어/영어 키와 레이아웃 확인.
- `release-preflight`: 릴리즈/푸시/패키징 전 최종 점검.

## 4. 추천 workflow

1. 접수: 요청을 데이터, 런타임, UI, i18n, 밸런스, 서사, 릴리즈, 혼합 작업으로 분류합니다.
2. 읽기: `AGENTS.md`, 기준 문서, 가까운 코드를 읽습니다.
3. 수정: 가장 작은 단위로 일관성 있게 패치합니다.
4. 검증: 검증 매트릭스에 맞는 명령을 실행합니다.
5. 기록: 임시 QA 산출물은 `_workspace/` 아래에만 둡니다.
6. 인계: 변경 파일, 동작 변화, 명령 결과, 남은 위험을 요약합니다.

## 5. `AGENTS.md`에 들어갈 규칙

Codex가 다음을 지키도록 합니다.

- 정적 HTML + React CDN 구조 유지.
- 개인 경로, 계정 정보, 토큰, API 키, 로컬 비밀 정보 기록 금지.
- 관련 없는 재작성과 사용자 변경 되돌리기 금지.
- 데이터 변경 후 `node tools/validator.js`.
- 런타임/UI 변경 후 로컬 브라우저 스모크.
- 밸런스 영향 변경 후 시뮬레이터 실행.
- `_workspace/`는 기준 상태가 아닌 임시 작업 공간.

## 6. `_workspace` 사용 기준

사용해도 되는 것:

- 임시 QA 리포트
- 시뮬레이션 JSON 출력
- 정식 데이터 반영 전 드래프트
- 스크린샷 또는 브라우저 점검 메모
- 릴리즈 패키징 산출물

사용하면 안 되는 것:

- 기준 설계 문서
- 프로덕션 코드
- 커밋해야 하는 릴리즈 상태
- 비밀키, 계정 정보, 개인 경로, 로컬 머신 정보

## 7. 과설계될 수 있는 부분

- 역할 파일이 너무 많으면 작은 수정이 느려집니다. 에이전트 문서는 필수 절차가 아니라 라우팅 프롬프트로 씁니다.
- Claude 에이전트를 1:1로 복제하지 않습니다. Codex에는 구현과 검증 흐름이 더 중요합니다.
- 하네스를 위해 빌드 시스템을 만들지 않습니다.
- 모든 콘텐츠 수정에 전체 릴리즈 QA를 강제하지 않습니다. 위험도에 맞게 검증합니다.
- 모든 임시 메모를 영구 보존하지 않습니다. `_workspace/`는 두 번째 아카이브가 아니라 작업 공간입니다.
