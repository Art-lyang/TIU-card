## 0. 개요

**Akashic Records (아카식레코드)** — Observer가 시공간 능력으로 운용하는 메타 아카이브. ORACLE 시스템의 외부이자 내부에 동시에 존재.

**핵심 설정**:
- ORACLE은 이 공간의 존재를 인지하지 못함.
- 접속한 사용자만 이를 볼 수 있음.
- Observer가 특정 관측자에게만 자료를 노출하는 선택적 우회 능력의 결과.

**인-유니버스 의미**:
- 플레이어가 이 아카이브를 발견한 것 자체가 **Observer의 허용**. 우연이 아니라 선택.
- TIU 핵심 주제 "자유의지라 믿는 것이 설계된 것이라면"의 플레이어 포함 구현.

## 2. 인-유니버스 성격 — W-3 암시적 표현

### 2.1 원칙

ORACLE과의 관계는 **아카이브 내부에서 명시하지 않음**. 플레이어가 ORACLE UI와 비교하며 스스로 추론하도록.

### 2.2 구체 표현

- "ORACLE이 이 공간을 모른다"는 문장은 아카이브 어디에도 쓰지 않음.
- 대신 다음 방식으로 암시:
  - ORACLE UI와 완전히 다른 미학 (§6).
  - ORACLE UI가 공식 서사로 기록한 사건에 대해 **정반대 기록**을 병렬 배치 (예: 강원도 사건 "민간 피해 없음" 공식 vs 유족 편지).
  - 자료 곳곳에 ORACLE 시스템을 제3자로 지칭하는 구절. "그 시스템은 기록하지 않았다" / "자료는 보관되지 않았다" 등.
  - 서두 또는 푸터에 **경고성 문구** 배치: "이 기록이 언제까지 보존될지 알 수 없다." / "관측은 의지에 달려 있다."

### 2.3 플레이어 발견의 순간

플레이어가 ORACLE UI 사이트와 이 아카이브를 교차 참조하는 순간 **비대칭 구조**를 깨닫도록 설계. 이 깨달음 자체가 서사적 경험.

## 3. 화자·수집자 — W-4 복수 병렬

### 3.1 외피

아카이브 전체는 "미래의 누군가가 남긴 기록 모음" 형식으로 보일 수 있음. 그러나 서두·편집자 주석·화자 정체는 **의도적으로 모호**.

### 3.2 실제 자료 출처 (병렬)

자료마다 명시되는 출처가 다름:

- **개인 수기·편지**: 가족·친지·전직 실무자의 사적 기록
- **전직 의료진 익명 증언**: 녹취록 형식. 이름 마스킹.
- **프로메테우스 내부 메모** (암시): 유출된 작전관 기록 단편
- **한국 정부 기밀 해제 문서**: 수십 년 후 해제된 가상 양식. 상당 부분 REDACTED.
- **외신 기사 스크랩**: 제3자 시점 기사. 공식 찬사와 드문 의심 병렬.
- **손상된 영상·음성 파일 캡처** (후속): 스크린샷·프레임 단위로 기록.

### 3.3 수집 주체의 모호성

각 자료가 **누구에 의해 수집되었는지는 모호**. "편집자" 존재는 느껴지나 이름 없음. Observer의 큐레이션일 수도, 미래의 누군가일 수도, 플레이어 자신의 발견일 수도 있다는 복합성 유지.

## 4. 접근 방식 — W-2 구현안 (시각 단서 + 숨겨진 URL)

### 4.1 기본 원칙

- 사이트 어디에도 `AKASHIC RECORDS` 링크 명시 없음.
- 진입 경로는 **시각 단서 발견 → URL 추론 또는 클릭**.
- 완전 숨김이 아니라 "눈썰미 있는 방문자가 찾는" 수준의 난이도.

### 4.2 구현 — 이스터에그 클릭 포인트 (확정)

특정 페이지의 시각 요소에 숨겨진 클릭 가능 영역 배치. 사이트 어디에도 표면적 링크 없음.

- **위치 후보** (1개 선택 또는 복수 배치):
  - 메인 페이지 THREAT MAP의 특정 비공식 좌표 (예: 지도 여백)
  - Turtle Isle 로고의 거북 아이콘 우측 하단 모서리
  - `protocols.html` 하단의 ORACLE 경고 띠 특정 문자
  - `database.html`의 검색 입력창 주변
- **시각 표시**:
  - 평상시 보이지 않음 (투명 또는 배경과 동색)
  - 마우스 호버 시 미세한 커서 변경 + 희미한 글로우
  - 클릭 시 `/akashic/` 로 이동

**구현 코드 예시** (HTML + CSS):

```html
<!-- 메인 페이지 어딘가에 배치 -->
<a href="/akashic/" class="hidden-entry" aria-label=""></a>

<style>
.hidden-entry {
  position: absolute;
  /* 위치는 배치 페이지에 따라 조정 */
  top: 420px;
  left: 812px;
  width: 14px;
  height: 14px;
  opacity: 0;
  cursor: default;
  transition: opacity 0.8s ease;
  z-index: 100;
}
.hidden-entry:hover {
  opacity: 0.35;
  cursor: pointer;
  box-shadow: 0 0 8px 2px rgba(255, 255, 255, 0.2);
}
</style>
```

### 4.3 추가 접근 수단

- **직접 URL 진입**: `/akashic/` 자체도 유효. 공식 어디에도 명시 없음. 눈썰미로 못 찾은 사용자의 우회 경로.
- **콘솔 힌트**: 현 시점에서는 미도입. 후속 확장 시 검토 가능.

### 4.4 진입 이후

- `/akashic/` 페이지는 ORACLE UI와 완전히 다른 미학으로 로드.
- 첫 화면은 짧은 암시 텍스트 + "ENTRIES" 목록.
- 돌아가는 링크는 제공하되 **ORACLE UI로의 복귀만** 가능. 아카이브 내부 네비게이션은 자체 시스템.

## 5. 자료 종류 — W-5 권장 4종

### 5.1 텍스트 문서

- 편지·수기·보고서·녹취록 원고
- 기본 표기: 흑·백 또는 세피아 톤. 일반 웹 텍스트 대비 강조.

### 5.2 이미지

- 스캔된 손글씨·오래된 사진·훼손된 이미지
- CSS 필터(sepia·grain·blur)로 질감 연출

### 5.3 기밀 해제 공식 문서

- 타자기체 폰트, REDACTED 블록, 도장·서명 이미지
- 특정 단어·문장을 검은 직사각형으로 마스킹 — "[REDACTED]" 또는 ███████

### 5.4 증언 녹취록

- 대화체 형식. 발언자 `A:`, `B:` 같은 익명 표시.
- 장시간 침묵이나 훼손된 구간은 `[...]` 또는 `[INAUDIBLE]`로 표기.

### 5.5 후속 확장 (보류)

- 영상·음성 파일 (구현 비용 높음)
- 외신 기사 스크랩 레이아웃
- 손상된 영상 프레임 스크린샷 시퀀스

## 6. 미학·디자인 톤 — W-7 C안 자료별 상이

### 6.1 기본 원칙

- ORACLE UI는 미래적·터미널·감시. 아카이브는 그 반대편 — **인간적·아날로그·마모된 질감**.
- 단, 자료 종류별로 세부 미학이 다름 (C안).

### 6.2 자료별 미학

- **편지·수기**: 세피아·구겨진 종이 배경. 손글씨 폰트.
- **공식 문서**: 타자기체. REDACTED 블록. 오래된 용지.
- **증언 녹취록**: 단색 모노스페이스 폰트. 간결·중립적.
- **이미지**: CSS 필터로 질감 부여.
- **외신 기사**: 신문 인쇄 양식 모방.

### 6.3 전체 공통 요소

- 배경색: ORACLE UI의 블랙과 대비되는 **누런 종이색(오프화이트 + 베이지)**.
- 헤더 `AKASHIC RECORDS`는 **세리프체**. ORACLE의 산세리프와 대비.
- 페이지 경계에 희미한 얼룩·그림자 — 오래된 문서 감각.
- 전환 애니메이션: 페이지 간 전환 시 잠깐의 지연·페이드. 디지털이 아닌 "들춰보는" 감각.

### 6.4 글리치·훼손 요소 (가끔)

- 자료 일부에 의도적 글리치 — 한 문장이 잠시 깨졌다가 복구되는 식.
- Observer의 불안정성 암시.
- 남용 금지 — 희소성이 효과를 만듦.

## 7. 수록 범위·수위 — W-9 암시 중심 (중요 원칙)

### 7.1 절대 원칙

- **핵심 캐논은 결코 완전 공개되지 않음.** 특히:
  - DG 2000년 역사 전체
  - Observer의 실체·기원
  - L4 구조
  - ORACLE의 자기 인식 전모
  - 의식 흔적 데이터의 정부 측 공식 인정
- 위 내용은 **암시·단편·모호함을 통해서만** 접근.

### 7.2 수위 판단 기준

각 자료마다 다음 질문을 통과해야 수록:

1. 이 자료를 읽은 후에도 **핵심 미스터리가 여전히 미스터리로 남는가?**
2. 자료의 화자는 **부분 진실**만 알고 있는가?
3. 자료는 **복수 해석 가능**한가?
4. 자료는 REDACTED 블록 또는 미완결 구조를 포함하는가?

세 개 이상 YES여야 수록 가능.

### 7.3 REDACTED 활용

- 결정적 고유명사(인물·장소·조직명)는 REDACTED로 처리.
- 페이지·날짜·사건 번호 일부만 공개.
- "보여주지 않음"이 "보여줌"보다 강력하다는 호러 장르 원칙.

## 8. 접근 제한 — W-8 공개 + 경고 문구

### 8.1 기술적 접근

- 한 번 URL에 도달하면 누구나 열람 가능.
- 시간 제한·퍼즐·권한 체계 없음.

### 8.2 인-유니버스 경고

각 자료 상단 또는 푸터에 경고성 문구 배치:

- "이 기록이 언제까지 보존될지 알 수 없다."
- "관측은 의지에 달려 있다."
- "다음에 이 자료를 찾을 때 그 자리에 있을 거라 확신하지 마라."
- "당신이 이것을 보고 있다는 사실 자체가 기록된다."

실제 접근 제한은 없지만 **심리적 긴장감만** 빌려옴.

### 8.3 푸터 고정 문구

모든 아카식레코드 페이지 하단 공통:

```
OBSERVED // UNRECORDED
```

또는:

```
NOT LOGGED BY THE SYSTEM.
```

## 9. 1차 수록 자료 (W-6 확정)

1차 공개 3종 (각 자료 상세는 `TIU-ARCHIVE-ENTRIES.md`):

### 9.1 ENTRY #001 — 강원도 사건의 진짜 모습

- **구성**: 유족 편지 1통 + 전직 경비병 익명 증언 녹취록 1건 + 기밀 해제 보고서 (일부 REDACTED)
- **암시 수위**: 민간 피해 존재 + 작전 중 바이러스 확산 암시. 최우진 이름 직접 언급 없음 — "고위직 가족" 정도의 간접 암시.

### 9.2 ENTRY #002 — 의식의 흔적

- **구성**: 전직 의료진 익명 증언 녹취록 1건 + 익명 학자의 미완성 논문 초고 단편
- **암시 수위**: Phase 1 개체의 잔존 반응 사례 암시. 결정적 증거는 REDACTED. 권세민 이름 직접 언급 없음 — "한 연구자"로만.

### 9.3 ENTRY #003 — 돌아오지 못한 자들

- **구성**: 입경 금기와 관련된 과거 기록 단편 + 프로메테우스 내부 메모 유출 추정 자료
- **암시 수위**: 북한 진입 시도 실패 사례 존재 암시. 구체 사실은 거의 모두 REDACTED. 생존자(혹은 그 일부)가 "다른 것이 되어" 돌아왔다는 표현만.

### 9.4 ENTRY 부여 원칙

- 번호는 순차이되 **전체 범위는 표시 안 함** (ENTRY #001이 첫째인지, 전체 중 몇 번째인지 불명).
- 미공개된 ENTRY가 있을 수 있음을 암시만 함.
