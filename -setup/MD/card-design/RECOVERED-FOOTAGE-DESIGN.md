# RF-Ω — RECOVERED FOOTAGE // Z-Ω 시리즈

> 필라델피아 Z-Ω 붕괴 당시·직후 민간 기기에서 회수된 SPEC 촬영본을
> "기이한 것들"(아날로그 호러 아카이빙) 스타일로 게임 안에 제시하는 콘텐츠 시리즈.
> 생존자·영상의 한국 유입 브리지는 **불필요** — 영상은 ORACLE DB에만 존재하고,
> 플레이어(관리자)는 열람 권한으로 본다. 캐논 마찰 0.

## 1. 컨셉

레퍼런스 스타일: 저화질 기록물(폰 촬영·바디캠·방송 캡처)을 **무표정한 기록자 톤**으로
아카이빙하는 숏폼 호러 포맷. 편집자는 놀라지 않고, 판단하지 않고, 기록만 한다.

인유니버스 매핑이 그대로 성립한다:

| 레퍼런스 요소 | TIU 대응 |
|---|---|
| 무표정 내레이터 | ORACLE 보고서 톤 (기존 아카이브 문법 그대로) |
| 저화질·손상 푸티지 | Z-Ω 붕괴 현장 회수 기기 (물리 손상·전송 중단) |
| "이게 뭔지 모른다"는 여백 | 접근 권한 검열(██, OMEGA CLEARANCE) |
| 촬영자의 행방 불명 | 캐논 수치: 필라델피아+캠든 미확인 66% (약 125만) |

공포의 축은 둘이다: ① 영상 속 SPEC의 기이함, ② **촬영자의 생사가 매 엔트리의
미해결 질문**이라는 점. ORACLE은 둘 다 감정 없이 처리하고, 그 온도차가 호러가 된다.

캐논 근거 (이미 깔려 있는 것):
- 강도윤 이브닝 챗: "필라델피아 Z-Ω 구역 영상... 보신 적 있으십니까." / "영상에서
  바다 쪽으로 뭔가 있었습니다. 크기를 가늠할 수 없었습니다." (`TIU-WORLDBUILDING-SUMMARY.md`)
- SPEC-005 Shell Walker: "Philadelphia Zone 해안 외곽에서 주로 관측… ORACLE
  데이터베이스를 통한 열람." — **"직접 조우 없이 DB 열람"이라는 프레임이 이미 캐논.**
- `TIU-USA-ORACLE-REPORT.md`: 이재민·음모론·정보 통제(NBS) 전부 확정 수치 존재.

## 2. 인유니버스 프레임

- **시리즈 코드**: `RF-Ω-##` (Recovered Footage / Zone Omega)
- **출처**: 붕괴 후 무인 회수 작전·드론 스윕에서 수거된 민간 기기, 순직 대원 바디캠,
  중단된 라이브 방송 서버 캐시.
- **열람 근거**: KR-INIT-001 관리자 교육 자료. 봉쇄선 중요성 상기용 — 캐논에 이미
  "교육 사례"로 명시된 용도를 그대로 쓴다.
- **번호는 불연속**으로 쓴다 (07, 12, 19…). 공개되지 않은 번호가 더 있다는 함의
  자체가 시리즈의 공포 장치다.

## 3. 아카이브 엔트리 포맷 (사건 카테고리)

`data-archive.js` `ARCHIVE_ENTRIES` 추가. `id`: `ARC-INC-RF##`, `cat`: `"사건"`.
본문 고정 골격:

```
RECOVERED FOOTAGE // Z-Ω-{번호}

회수 위치: {장소} / 기기: {기기 유형·상태}
총 길이: {n분 n초} (재생 가능 구간 {n초})

[00:00:00] {타임코드 서술. 사실만. 형용사 최소.}
[00:00:00] {…}
[데이터 손상 — {n}초 유실]
[00:00:00] {…}

기록 종료 사유: {전송 중단 / 기기 파손 / 배터리 방전 …}
촬영자 상태: 미확인
ORACLE 판정: {모델 대조 결과 한 줄. 영문 인용 가능}
```

포맷 규칙:
- 타임코드 서술은 **카메라가 본 것만** 적는다. 해석·감정어 금지. 무서운 문장을
  쓰지 말고, 무서운 사실을 평서문으로 쓴다.
- `[데이터 손상]` 결손 구간이 절정 직전에 오게 배치한다. 보여주지 않는 게 규칙.
- `촬영자 상태: 미확인`은 시리즈 전체 고정 문구. 단 한 번도 "사망"이라 쓰지 않는다.
- ORACLE 판정은 기존 캐논 문법의 영문 한 줄로 닫는다
  (예: *"Footage does not contradict model. Subject count does."*).
- 검열은 기존 아카이브와 동일하게 `██` / `OMEGA CLEARANCE REQUIRED`.

## 5. 해금 설계

**1단계(저비용, 신규 LOG 없음)** — 기존 LOG 재사용으로 즉시 편입 가능:

| 엔트리 | unlock 제안 | 근거 |
|---|---|---|
| ARC-INC-RF07 | `LOG-013` | SPEC-001 계열과 동일 트리거 — 본체 스펙을 알게 된 뒤 푸티지 열람 |
| ARC-INC-RF12 | `LOG-004` | ARC-SPEC-011(Shell Talker)과 페어 |
| ARC-INC-RF19 | `LOG-INTRO-KD` | ARC-SPEC-009(TS-Ω)와 동일 — 강도윤 대사 라인과 직결 |

**2단계(선택)** — 전용 신규 LOG(`LOG-RF-*`)로 체인화할 경우, **같은 커밋에서**
`oracleLogs` EN 오버레이(`lang-content-en-all.js` 또는 `lang-cards-flow-en.js`)를
짝으로 추가한다 (CLAUDE.md Mission i18n Rule).

Act 배치: 열람 개방은 Act 2(green, 탐색)부터. RF19(TS-Ω)는 Act 3(yellow) 이후
권장 — 규모 공포는 압력 구간에 놓는 게 색상 정체성과 맞는다.

## 6. i18n

- 아카이브 EN 짝: `lang-archive-en.js`의 `archiveEntries`에 `title`/`content` EN 추가
  (+ `demo/` 미러). `cat` 매핑("사건" → "Incident")은 `lang-content-en-all.js`의
  `archiveEntries` cat 오버레이 확인.
- 타임코드·`RECOVERED FOOTAGE` 헤더 등 영문 고정 표기는 KO/EN 공통으로 둔다.

## 7. 영상 자산 (선택 확장)

1단계는 **텍스트 온리**로 완결된다 (결손·검열이 핵심 장치라 텍스트가 오히려 유리).
실영상을 붙일 경우:
- `CCTV_CLIPS`(`components-game.js`)는 미션 스팅 전용이므로 재사용하지 않는다.
  아카이브 뷰어 쪽 별도 임베드로 설계하고, 규격은 동일하게 **H.264(avc1)+faststart**.
- 파일 경로 `assets/video/rf-*.mp4`, 캐시 태그는 `node tools/stamp-cache.js` 일괄.
- 스타일 가이드: 세로/저해상·타임코드 오버레이·컷 없음(원테이크 위장)·절정 직전 컷아웃.
